# ============================================================================
# v9.0/v10.1 — OCR LOCAL CON LLAMA.CPP + VULKAN (GPU AMD, MULTI-MODELO)
# ============================================================================
# NO requiere ningún paquete de pip: el motor es un SERVIDOR EXTERNO
# (llama-server, compilado con backend Vulkan) que sirve un modelo de OCR
# por HTTP en localhost:8080 con API compatible OpenAI. Pensado para GPUs
# AMD de consumo SIN soporte ROCm oficial (RX 6700 XT / gfx1031): Vulkan sí
# funciona en esas tarjetas.
#
# v10.1 — Familias servibles (OCR_LLAMACPP_FAMILIA en .env): GLM-OCR
# (0.9B, default), HunyuanOCR-1.5, olmOCR-2-7B o genérico. Ver README
# sección "OCR local con llama.cpp + Vulkan" (comandos por familia).
#
# Activación (después de arrancar el servidor):
#     .env:  OCR_BACKEND=llamacpp
#            OCR_LLAMACPP_URL=http://localhost:8080     (default)
#            OCR_LLAMACPP_FAMILIA=glm-ocr               (default v10.1)
#
# Opcional, SOLO para descargar el modelo desde HuggingFace con el comando
# `huggingface-cli` del README (también puedes bajarlo a mano con el
# navegador, o directamente dejar que `-hf` lo descargue solo). NO se
# instala desde aquí: es un comando de consola, no un paquete de este
# archivo (una línea 'pip install ...' dentro de requirements.txt rompe
# 'pip install -r requirements.txt').
#     pip install -U "huggingface_hub[cli]"
#
# v10.0 — Con el servidor arrancado, la cascada de OCR es 100% LOCAL:
#     pypdf -> OCR local (gratis, manuscritos incluidos) -> fallo
# explícito; y si el servidor NO está arrancado, se avisa UNA vez y el
# PDF queda SIN TEXTO (sin cachear): NADA se escala a la nube (v10.0).
